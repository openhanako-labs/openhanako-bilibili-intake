# Intake Summary — 结构化总结 + 可回指校验

## 它解决什么

过去的总结层没有"对不对"的概念：模型读完正文写一段话，没人知道哪句来自原文哪一段——编了也看不出来。这里给总结一个**可验证的形状**，每个要点必须能回指到正文锚点，回指不到的明确标出来。它是仪表盘，不是门卫：校验不过也照样存，只如实报告。

## 产物

每个产物目录下落 `summary.json`（机器读）+ `summary.md`（人看）：

- `brief`：卡片级一句话（写进记录的 summary 字段）
- `points[]`：要点，每个 `{ text, at, anchor, verified, match, score, reason }`
- `counts`：`要点 N · 可回指 X · 未回指 Y`
- 覆盖前自动留档到 `summary-history/`，不同版本可回溯
- 回写记录字段，卡片直接显示"要点 N · 未回指 M"

## 锚点按内容类型走（anchorKind 决定出处怎么给）

| 内容类型 | anchorKind | 出处 at 怎么写 |
|---|---|---|
| 视频 video | `time` 时间轴 | `at: "12:30"`（锚到秒区间） |
| 文章 article / 文档 document | `section` 小节 | `at: "§3"` 或 `"第3节"` |

不写 `at` 也行：工具按逐字最长公共子串去正文找最像的一段，匹配度 ≥0.5 才算回指成功；找不到就标"回指不到"并提示你显式给 `at`。

## 用法

```typescript
{
  action,      // save(默认，校验并落盘) / check(只校验不落盘，先试) / read(读回已存)
  recordId,    // 推荐：采集回执里的「记录ID」
  source,      // 或 BV号 / 链接 / 本地文件路径 / 标题片段，自动定位记录
  slotDir,     // 或直接给产物目录（定位不到记录时）
  brief,       // 一句话摘要
  points,      // 要点列表，每项 { text, at? }；至少 1 条
  model, promptVersion,   // 可选：记录谁写的、哪版 prompt
}
```

定位优先级：`recordId` > `source` > `slotDir`。所以采集完直接拿回执的「记录ID」最稳。

## 想要更细，四个刻度

1. **多给 points、每个锚更精确**：视频锚到更细的秒、文档锚到更小小节；先 `action=check` 试、迭代到回指干净（ungrounded 归零）再 `action=save`。
2. **分段喂**：长内容在采集层就用 `anchorOffset` / `anchorLimit` 控制一次看多少，再分部写要点。
3. **留档对比**：每次重写进 `summary-history/`，可比较不同粒度/不同版的总结。
4. **要的是学习路径而非摘要**：上 `generate_knowledge_map`——它产出方向→阶段→知识点的树，比 summary 高一个层级。

## 为什么值得这么麻烦

可回指让"总结在编"第一次变成**可检查的**：`counts.ungrounded` 不为 0，就说明有些要点在正文里找不到逐字出处。给别人复核、或自己隔段时间回看，这是唯一的"翻译没走样的证据"。
